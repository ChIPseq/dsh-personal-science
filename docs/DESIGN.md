# 设计说明：为什么是 0 个工具

## 一、来自真实失败案例的三条证据

对一个月的真实科研工作区（`D:\workspace\ZhangLab-CPU`，32 个 session / 852 turn / 9,840 次工具调用 / 20 次上下文压缩）做会话日志分析后，得到三条结构性失败，而不是"记忆插件没装"：

1. **同一份分析文档被整体重写 295 次**（另一份 199 次）。它同时被当成草稿、结论台账、待办和工作记忆——角色混用导致写入方式只能选"整体重写"，295 个中间版本一个都没留下（项目没有 git）。
2. **20 次上下文压缩**把"为什么放弃某条路线"这类推理抹掉。失败原因只活在对话里。
3. **项目根堆积 200+ 个 `tmp_*.sh`**（`tmp_chk1..23`、`tmp_probe.sh` 重写 36 次），没有"这一步属于哪个实验"的归属，事后无法回收。

结论：缺的不是记录能力（agent 已经在自发维护 `Plan_Summary/`、claims ledger、执行记录），缺的是**角色分离 + 写入规则 + 自动注入**。

## 二、三条设计原则

### 1. 状态要注入，不要"请求"

两个已有的科研插件（`dsh-science`、`dsh-science-workbench`）都靠"模型自觉调用 `research_state` / `bio_get_project`"来维持状态。一旦模型这一轮没调，状态就断——而且模型无从知道自己断了。

DSH 的 `systemPrompt.context` 在**每次模型步**都会重新渲染，并以 "This snapshot supersedes earlier runtime-context snapshots" 的语义替换旧快照。于是状态存在性不再依赖模型的主动性。

这个 callback 拿不到 agent？——拿得到。`assembleContextFor(agent, signal)` 返回 `{ agent, scope: agent, ... }`，全局注册的 context 对每个 agent 都会收到它。

### 2. 台账要由事件写，不要由模型写

`tools/result` 是 emit 事件，携带 `exec.agent` 与 `exec.arguments`。挂在上面写 JSONL，模型无法"忘记记账"。

代价是记账很粗（只有工具名、签名、成败），但**粗而必有的证据**胜过**细而可漏的证据**。需要精细溯源时，由模型把某次结果"提升"为正式产物——这是后续版本的事。

### 3. opt-in 用目录存在性表达

`<cwd>/sci/` 存在 = 这是科研项目。没有就什么都不做。

这一条是为了让插件可以常驻 profile：代码仓库、临时目录、别人的项目里不会被写入任何东西。

## 三、文件角色与写入规则

| 文件 | 角色 | 写入方式 | 理由 |
|---|---|---|---|
| `sci/STATE.md` | 当前状态快照 | 唯一允许整体重写；<= 45 行 / 1800 字 | 它会进每一步的上下文，必须小且必须是最新的 |
| `sci/log/<日期>.md` | 会话日志 | 只追加 | 追加 = 天然版本化 |
| `sci/dead-ends.md` | 死路台账 | 只追加 | 失败信息一旦被"整理"就会失真 |
| `sci/ledger/*.jsonl` | 工具台账 | 仅插件写 | 机器事实，人不该编辑 |
| `sci/branches.json` | 分支树 | 仅插件 + `/branch` 写 | 从 session header 还原，人是补语义 |
| `sci/state-history/` | 快照归档 | 仅 `/wrap` 写 | 让"重写"也可追溯 |

**核心规则：分析文档、方案文档、论文稿只允许追加节，不允许整体重写。** 这条写进了 skill，因为它正是 295 次重写的直接成因。

## 四、为什么记 branch

DSH 支持"在新对话中分支"：新会话 `isSeeded: true` 且 header 带 `parentSession`。这是科研里最重要的操作之一——岔路口选一个方向试。

原始案例里分支链是 `2d55e43c → 04a9d50d → 00b16915 → b9f5cfaa → ff71a1e3`，但**没有任何地方记录每个分支要验证什么**，一个月后只能靠 session id 猜。

插件在 `agent/created` 时把节点写入 `branches.json`（不需要模型参与），分支的**语义**由 `/branch <一句话>` 补。fork 出来的会话会在每一步的注入里看到"自己是某个会话的分支，方向是 X"。

## 五、与记忆插件的边界

- `sci/` = 项目状态：项目内、可 git、人可读、进上下文。
- 记忆插件 = 个人知识：跨项目、失败模式、方法偏好、领域事实。

两边都不抄对方的内容：`sci/` 回答"这个项目现在怎样"，记忆回答"我在科研上学会了什么"。下一版会让 `/deadend` 同时写一条 `contextual` 记忆（带 project 标签）。

## 六、已知取舍（v0 不做）

- 不做 UI。Client bundle 是 80% 工作量换 20% 收益，等 dogfood 出真需求。
- 不做远程作业管理。`pwsh` + `ssh` 原生能力足够；台账会自动记录提交命令。
- 不做文献库/引文管理。先把"状态不断线"这件事做对。
- 不做语义检索的死路匹配。STATE 里已有 top-3 摘要，关键词命中留给 v0.2。
